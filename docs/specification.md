# VividAI ComfyUI 节点包：首版确认规格

状态：用户于 2026-10-17 确认并授权实现。许可证：MIT。

## 产品与交付

- 面向 VividAI 用户公开发布，Python 自定义节点包，按跨平台方式实现。
- Windows 首发并进行端到端验收；其他系统的验证状态如实记录。
- 以实际开始开发时 ComfyUI 官方最新稳定版为兼容基线，记录具体版本。
- 使用 uv 创建项目虚拟环境和管理开发依赖；使用 Git 版本控制。
- 每完成一项可验证任务，单独提交 Git，提交记录和进度文件记录验证依据。
- 交付安装说明、示例工作流、测试及测试记录。公开发布/上架不属于本轮外部操作。

## 四个节点

| 节点 | 作用 | 输出 |
| --- | --- | --- |
| VividAI 配置 | 在节点界面管理本机 API 凭据，选择配置引用 | 连接配置引用 |
| VividAI 文生图 | 提示词生成一张图片 | 原生 IMAGE |
| VividAI 文生视频 | 提示词生成一份视频 | 原生 VIDEO |
| VividAI 参考素材生视频 | 提示词结合编号参考素材生成一份视频 | 原生 VIDEO |

配置引用只标识本机连接配置，不包含 Key。API Key 通过独立的保存交互写入本机凭据存储，不能进入节点参数序列化、工作流、素材元数据或日志。

## 动态模型与能力配置

- 使用现有 VividAI API，不要求服务端扩展接口。
- 从 `GET /v1/models` 动态取得全部模型 ID，不写死具体型号或按名称猜测能力。
- 各生成节点独立保存各模型的能力配置，配置随工作流导出。
- 主区域选择本次生成参数；展开区编辑该模型的素材上限、清晰度、比例、时长可选值/范围及必填规则。
- 新模型使用可编辑的默认能力模板。参考素材默认 933，即最多 9 图、3 视频、3 音频。
- 下拉列表刷新失败或型号下架不能阻止复用本机已有素材；真正生成时进行相应验证与明确报错。

## 素材输入

- 参考素材生视频固定提供 9 个 IMAGE、3 个 VIDEO、3 个 AUDIO 编号输入。
- 一个端口表示一份素材，提交顺序与各类素材编号一致。
- 物理端口数量固定，模型规则只能减少启用数量，不能扩容。
- 不支持的端口仍保持标识与连线，界面明确标示禁用。
- 使用惰性输入阻止本节点请求禁用素材的上游计算；不读取、不编码、不上传禁用素材。
- 已有素材且没有重新生成标记时，也不为本节点输出请求生成所需的上游素材。
- 其他独立执行分支仍可能请求同一上游，这是 ComfyUI 的图执行边界。

## 生成、复用与重新生成

- 初次没有可用素材时，正常运行工作流生成一份素材。
- 已有素材时，默认输出当前选中的素材，即使提示词、模型、参数或上游输入发生变化。
- 修改参数显示“参数已修改，重新生成后生效”，不得自动创建付费任务。
- 按钮文案为“下次运行重新生成”，只标记当前节点，不立即执行。
- 下一次运行使用该节点当前参数生成一份素材；一次标记对应一次新生成意图。
- 同一生成意图重复执行应恢复已知任务，不能因重试重复创建任务。
- 每个节点独立维护持久身份、任务与素材记录；复制节点创建新身份，不共享生成结果。
- 保存并重新打开同一工作流，保留节点身份，以便恢复本机记录。

## 历史素材队列

- 每个节点独立维护容量为 N 的素材队列，默认 N=3，可在节点中配置。
- 新素材成功下载和校验后进入队头；生成失败不挤占队列。
- 用户可以快速预览、启用队列中的任意素材，启用后该素材移至队头。
- 启用历史素材只切换输出，不改写当前模型、提示词或参数；详情可以显示生成时的参数快照。
- 超出容量淘汰队尾，并清理仅由插件管理的对应缓存；不删除通过保存节点另存的用户文件。
- 正在被执行任务读取的文件需要延迟物理删除，不能在使用中破坏文件。
- 历史缓存、任务状态和选中素材在本机持久保存，支持 ComfyUI 重启后恢复。

## 远程任务协议与故障处理

以 2026-10-17 浏览器读取的 VividAI 当前官网为准，Context7 中旧的 `/v1/videos`、`/v1/images/generations` 方案不作为实现依据。

1. `POST /v1/uploads` 申请上传地址，按返回的 URL 使用 PUT 上传，Content-Type 与申请的 MIME 完全一致。
2. `POST /v1/generate` 提交 model、prompt、quality、ratio、duration、refs 等文档规定字段。
3. 响应为 NDJSON：首行返回 jobId/running，空行心跳应忽略，终态为 succeeded/failed。
4. 获得 jobId 后立即持久记录；断线后只携带同一 jobId 重连，不创建新任务。
5. 达到等待上限后保留待恢复记录；下次可以继续恢复原任务。
6. 成功后及时下载临时结果 URL，校验成品并包装为 ComfyUI 原生 IMAGE/VIDEO。
7. 明确失败时显示错误并停止本次工作流，旧素材保留供用户手动启用；不自动回退继续下游。
8. 尚未取得 jobId 的提交异常属于结果不明确，不能盲目重新提交；通过明确状态提示交由用户决定是否标记新的生成。
9. 本地中断停止等待、保留任务信息；未有文档支持时不宣称已取消远程任务或保证退款。

上传文件上限、格式、过期时间与服务端固定约束按当前官方文档实现，不允许能力配置绕过服务约束。

## 验收重点

- 四个节点正确注册，原生 IMAGE/VIDEO 可以连接保存节点。
- 模型动态加载，模型规则独立持久化，工作流不含 Key。
- 固定编号端口及禁用/缓存命中场景的惰性行为正确。
- 修改参数不产生新付费任务，标记下一次生成恰当消费；复制节点不共享历史。
- 原任务断线重连、跨重启恢复、提交不明确、明确失败均有真实状态和测试。
- 队列默认 3、旧素材启用置顶、淘汰只清理插件缓存、文件使用中安全。
- 通过模拟服务验证上传、NDJSON、下载及重连；有可用本机环境时运行真实 ComfyUI 验收。
- 未取得服务凭据前不宣称已完成真实 VividAI 付费生成验证。
